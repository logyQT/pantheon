Pantheon Scripting Engine

JavaScript modules using GraalJS (GraalVM JavaScript) — ES2022+

Overview

Pantheon's scripting engine lets you write party games, chat commands, and chat hooks in pure JavaScript (ES2022+), powered by GraalVM JavaScript (GraalJS) via the GraalMC mod. Each module lives in its own folder under config/pantheon/scripts/ and is hot-reloaded via /pantheon reload.

Requirement: Pantheon requires GraalMC (GraalVM JavaScript for Minecraft) as a separate mod. Install it from Modrinth or CurseForge. Pantheon needs GraalMC to be present in the mods folder at runtime.

A module declares what it does by calling methods on 8 injected namespace globals (settings, command, chat, gui, game, economy, audio, core). The engine evaluates the script, discovers registered commands/game hooks/chat handlers, and wires them up.

Modules can be toggled on/off via the clickgui. When disabled, their hooks are not called — the script remains loaded but inactive.

Design Convention: If a method accepts more than 2 parameters, it uses an opts object. Examples: gui.button({ id, display, callback }), command.onCommand({ invoker, ... }), settings.slider({ id, default, ... }). No positional args beyond 2.

Module Structure

Folder layout

Each subfolder under config/pantheon/scripts/ is a module. The folder name becomes the module ID.

config/pantheon/scripts/
├── number_guesser/
│   └── module.js              ← entry point (loaded last)
├── ascii_pictures/
│   ├── module.js
│   └── picture-commands.json  ← module-local asset, read via core.readFile()
├── meow/
│   └── module.js
└── lib/
    └── utils.js               ← shared via require('../lib/utils')

manifest.json

Each module can include a manifest.json that lists files to copy on first install. Format: a JSON array of filenames. If omitted, only module.js is copied.

["module.js"]
["module.js", "admins.json", "picture-commands.json"]

File size limit

Individual .js files exceeding 10 MB are skipped with an error logged to console. The module still loads if other files are below the limit.

Entry point

module.js is evaluated last, after all other .js files in the folder. Functions and variables defined in sibling files are available to module.js.

require(path)

Contract: Loads a sibling file and returns its exports object. Path resolves relative to the module folder. Each module has its own require cache.
Pattern: Use exports.foo = ... to expose values. Do not reassign exports directly. 
// helpers.js
exports.pickRandom = function(arr) {
  return arr[Math.floor(Math.random() * arr.length)];
};

// module.js
var helpers = require('./helpers');
helpers.pickRandom([1, 2, 3]);

Hot reload

Run /pantheon reload to reload all modules. Failed modules are skipped with chat feedback. All state is lost on reload — clean up timers in game.onStop().

Settings persistence

Settings define configurable values that persist to config/pantheon/config.json. They have no GUI knowledge — you bind a setting to a GUI widget later via gui.slider/gui.toggle/gui.text.

Pattern: Call settings.category() and settings.displayName() at the top of module.js. Then declare settings with settings.slider/toggle/text. Values persist automatically. If you don't bind a setting to a GUI widget, it still exists in the config file but won't appear in the clickgui.

settings.category(name)

Groups this module under a named panel in the clickgui. Default: "Scripted Modules".

settings.category("Party Games");

settings.displayName(name)

Human-readable name shown in the clickgui. Default: folder name as Title Case.

settings.displayName("Number Guesser");

settings.slider({ id, default, min, max, step })

Defines an integer setting with a range. Only id is required. Defaults: min: 0, max: 100, step: 1, default: 0.

settings.slider({ id: "reward", default: 10, min: 1, max: 100, step: 1 });

settings.toggle({ id, default })

Defines a boolean setting. default is false if omitted.

settings.toggle({ id: "enabled", default: true });

settings.text({ id, default })

Defines a string setting. default is "" if omitted.

settings.text({ id: "prefix", default: "!" });

settings.get(id) → value

Returns the raw value: Integer for sliders, Boolean for toggles, String for text settings. Returns the default value if not yet customized.

const reward = settings.get("reward");  // Integer
const enabled = settings.get("enabled"); // Boolean

settings.set(id, value)

Updates a setting at runtime. Persisted automatically. Fires onChange listeners.

settings.set("reward", 50);

settings.onChange(id, callback) → unsubscribe function

Registers a callback that fires when the setting changes (via settings.set() or the clickgui). Callback receives (newValue, oldValue). Returns a JS function you can call to unsubscribe. Warning: Calling settings.set() inside an onChange callback is silently ignored to prevent infinite loops.

const unsub = settings.onChange("reward", (newVal, oldVal) => {
    console.log(`Reward changed from ${oldVal} to ${newVal}`);
});
// Later: unsub();

GUI clickgui widgets

Widgets and buttons that appear in the clickgui when you right-click a module. Settings = persistence layer; GUI = visual widgets bound to settings by ID. You must declare a setting first (settings.slider/toggle/text), then bind it with its matching GUI method.

gui.slider({ id, display })

Binds a slider widget to an existing slider setting by ID. The display is the label shown in the clickgui.

gui.slider({ id: "reward", display: "Reward" });

gui.toggle({ id, display })

Binds a toggle widget to an existing toggle setting.

gui.toggle({ id: "enabled", display: "Enabled" });

gui.text({ id, display })

Binds a text input widget to an existing text setting.

gui.text({ id: "prefix", display: "Prefix" });

gui.button({ id, display, callback })

Adds an action button. Does not bind to a setting — it fires callback when clicked.

gui.button({ id: "open_folder", display: "Open Folder", callback: () => {
    gui.openFolder();
} });
gui.button({ id: "refresh", display: "Refresh", callback: () => {
    refreshPictures();
} });

gui.unregister(id)

Removes a previously registered button by ID.

gui.unregister("open_folder");

gui.openFolder()

gui.openFolder({ path })

Opens a folder in the system file explorer. With no args, opens config/pantheon/. With path, resolves relative to the module's directory. Path traversal is blocked.

gui.openFolder();
gui.openFolder({ path: "/assets" });

Commands

Chat Commands !name

Register !name commands that fire from party chat. Cross-module duplicate invokers are allowed — both handlers fire.

command.onCommand({ invoker, description, callback })

Contract: Registers a chat command. The callback receives (sender, args) where args is a String array of space-separated arguments after the command name. description is optional (shown in UI/debug). 
command.onCommand({
    invoker: "pictures",
    description: "List available ASCII pictures.",
    callback: (sender, args) => {
        chat.party(`Available: ${names.join(", ")}`);
    }
});

command.off(invoker)

Unregisters a chat command previously registered by this module. Scoped per-module — cannot unregister another module's command.

command.off("hello");

Client Commands /name

Register Brigadier-based /name commands using Fabric API. These are globally unique — the first module to register wins, the second throws.

command.onCommand({ invoker, type: "client", args, callback })

Contract: type: "client" registers a Brigadier command instead of a chat-queue command. args is an array of { name, type, optional } objects. Supported types: "string" (word), "number" (integer), "boolean", "player" (word), "greedy_string" (rest of input).
Max 5 args. The callback receives a single ctx object with ctx.get(name) (returns argument value or null) and ctx.getSender() (returns the player's username).
Note: Chat commands (!) and client commands (/) exist in separate namespaces. You can register !hello and /hello from the same module. 
command.onCommand({
    invoker: "warn",
    type: "client",
    description: "Warn a player.",
    args: [
        { name: "target", type: "player" },
        { name: "reason", type: "greedy_string", optional: true }
    ],
    callback: (ctx) => {
        const target = ctx.get("target");
        const reason = ctx.get("reason") || "No reason given";
        chat.party(`Warned ${target}: ${reason}`);
    }
});

Chat messaging

Send party/guild/all messages through a rate-limited queue, send local feedback, or listen for incoming messages.

chat.party(msg)

chat.guild(msg)

chat.all(msg)

Contract: Messages are queued and sent with a cooldown to avoid Hypixel rate limits. Messages over 200 characters are silently dropped. Prefixed with pc , gc , or ac . 
chat.party("Hello party!");
chat.guild("Hello guild!");
chat.all("Hello world!");

chat.command(cmd)

Sends a command (/hub, msg Notch hi) via the player's connection. Also queued for rate limiting. Max 200 chars.

chat.command("/hub");

chat.client(msg)

Contract: Sends a local-only message that only the mod user sees. No queue, no rate limit. Prefixed with [Pantheon] in gold. Silently dropped if the player is not in-game. 
chat.client("Score: 5");
chat.client("Pictures reloaded (5 commands).");

chat.raw(payload)

Contract: Escape hatch — sends raw text directly to the player's chat connection without any prefix, queue, or filtering. Bypasses all Pantheon formatting. Use for JSON chat components or when you need full control. 
chat.raw('{"text":"Hello!","color":"gold"}');

chat.onMessage(callback)

chat.onMessage(pattern, callback)

Contract: Registers a global chat hook that fires for every incoming message (party, guild, system, game messages), regardless of game state. With a pattern string, only fires when rawText.toLowerCase() contains pattern.toLowerCase(). The callback receives the raw message text. 
chat.onMessage((rawText) => {
    console.log("Got:", rawText);
});

chat.onMessage("meow", (rawText) => {
    audio.playSound({ sound: "minecraft:entity.cat.ambient" });
});

Economy currency

Server-wide integer coin economy backed by SQLite. Thread-safe. Shared across all modules and persists across restarts.

economy.add("Notch", 100);
const taken = economy.take("Notch", 50);   // false if insufficient
const bal = economy.balance("Notch");       // 50
const has = economy.has("Notch", 30);       // true
economy.set("Notch", 0);                    // reset to 0

Audio sounds

Play Minecraft sounds at the player's position.

audio.playSound({ sound, volume, pitch })

Only sound is required. volume and pitch default to 1.0. Silently does nothing if invalid or player not in a world.

audio.playSound({ sound: "minecraft:entity.cat.ambient" });
audio.playSound({ sound: "minecraft:block.note_block.pling", volume: 0.5, pitch: 1.5 });

File I/O

core.readFile(path)

Contract: Reads a UTF-8 file relative to the module folder. Returns the content as a string, or null if the file doesn't exist, is unreadable, or the resolved path escapes config/pantheon/scripts/. One level of ../ is allowed for shared lib folders. 
const data = JSON.parse(core.readFile("picture-commands.json"));
const shared = core.readFile("../lib/common.json");
// Blocked: core.readFile("../../config.json");  → null

core.httpRequestAsync(method, url, body, headersJson, callback)

Contract: Sends an HTTP request on a background thread (non-blocking). Returns immediately — the callback fires on the next client tick after the response arrives. Parameters: method — "GET", "POST", "PUT", "DELETE" (case-insensitive)
url — full URL string
body — request body string (ignored for GET/DELETE), or null
headersJson — JSON string of headers like {"Content-Type": "application/json"}, or null
callback — receives a single HttpResult object
Note: You rarely call this directly — use the fetch() polyfill instead.

HttpResult

The object passed to the callback has the following interface:

result.status       // HTTP status code (e.g. 200), or 0 on network error
result.body         // response body as a string
result.errorMessage // error message if network error, or null
result.isOk()       // true if 200-299
result.hasError()   // true if network error occurred

core.httpRequestAsync("GET", "https://api.example.com/data", null, null, function(result) {
    if (result.hasError()) {
        console.error("Request failed:", result.errorMessage);
        return;
    }
    console.log("Status:", result.status, "Body:", result.body);
});

Game Lifecycle games

Register lifecycle callbacks for modules that run as a game. Games are stateful — only one can be active at a time.

Methods:
game.start() — start the game (call from a command.onCommand() callback)
game.stop() — stop the game, release game slot
game.onStart(cb) — callback receives (sender)
game.onStop(cb) — callback receives (reason)
game.onChat(cb) — callback receives (sender, message)
game.onTick(cb) — callback receives no args

game.stop()

Ends the current game, releases the slot so other games can start. No-op if no game is active. Calls onStop callbacks.

game.stop();

game.onStart(callback)

Contract: Called when the game starts via game.start(). Games require an explicit command.onCommand() call to register a start command; the callback should call game.start() to trigger the game lifecycle. There is no auto-registration of commands for game modules. The callback receives the starter's username. 
game.onStart((sender) => {
    chat.party(`Game started by ${sender}!`);
});

game.onStop(callback)

Contract: Receives a reason string: "MANUAL" (via game.stop()), "RELOAD" (module being reloaded while running), "DISCONNECT" (player left), or "DISABLED" (module toggled off while running). Always clean up timers here. 
game.onStop((reason) => {
    if (timeoutId >= 0) clearTimeout(timeoutId);
});

game.onChat(callback)

Called for each party chat message while the game is active, except messages starting with ! (those are routed to CommandManager as commands). Receives (sender, message). Only fires during an active game — different from chat.onMessage which fires always for all chat channels.

game.onChat((sender, message) => {
    const guess = parseInt(message);
    if (!isNaN(guess)) checkGuess(sender, guess);
});

game.onTick(callback)

Called every client tick (~20 times/second) while the game is active.

game.onTick(() => {
    // Update countdown, check elapsed time, etc.
});

Timers

setTimeout(callback, ms)

clearTimeout(id)

Contract: Standard timer API. Fires on the main client thread (safe for Minecraft API access). Automatically cleaned up on module reload. Callback-first signature: setTimeout(fn, ms). setInterval is not available — use recursive setTimeout instead. 
const id = setTimeout(() => {
    chat.party("Time's up!");
    game.stop();
}, 10000);

clearTimeout(id);

// Repeating pattern with setTimeout:
function tick() {
    updateCountdown();
    setTimeout(tick, 1000);
}
tick();

Native GraalJS Globals

GraalJS provides many standard JavaScript globals out of the box. These are available in any script without imports.

console.log("Debug info");
console.warn("Something is off");
console.error("Error:", err);

const p = new Promise((resolve) => resolve(42));
const map = new Map();
const set = new Set();

fetch() — HTTP requests

A polyfill wrapping core.httpRequestAsync(). Requests run on a background thread — the Promise resolves on the next client tick after the response arrives. Does not block the game.

const res = await fetch("https://api.example.com/data");
const data = await res.json();   // full response body as object
// res.ok       — true if status 200-299
// res.status   — HTTP status code
// res.text()   — raw body as string
// res.json()   — parsed JSON

// With options:
const res2 = await fetch("https://api.example.com/data", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ key: "value" })
});
Note: setInterval is not available — GraalJS cannot create timer threads (allowCreateThread(false)). Use setTimeout with recursive calls if you need repeating execution.

Complete Examples

number_guesser/module.js — Game module

Demonstrates: settings, GUI, economy, timers, game lifecycle, chat input.

settings.category("Party Games");
settings.displayName("Number Guesser");

settings.slider({ id: "reward", default: 10, min: 1, max: 100, step: 1 });
settings.slider({ id: "timeout_ms", default: 15000, min: 5000, max: 60000, step: 1000 });
settings.slider({ id: "max_number", default: 20, min: 5, max: 100, step: 1 });

gui.slider({ id: "reward", display: "Reward" });
gui.slider({ id: "timeout_ms", display: "Timeout (ms)" });
gui.slider({ id: "max_number", display: "Max Number" });

command.onCommand({
    invoker: "guess",
    description: "Guess a number. Use !guess to start.",
    callback: (sender, args) => {
        game.start();
    }
});

let target = 0;
let hints = 0;
let timeoutId = -1;

game.onStart((sender) => {
    target = Math.floor(Math.random() * settings.get("max_number")) + 1;
    hints = 0;
    chat.party(`NUMBER GUESSER! I'm thinking of 1-${settings.get("max_number")}. ${sender} guesses first.`);
    timeoutId = setTimeout(() => {
        chat.party(`Time's up! The number was ${target}.`);
        game.stop();
    }, settings.get("timeout_ms"));
});

game.onChat((sender, message) => {
    const guess = parseInt(message);
    if (isNaN(guess)) return;
    hints++;
    if (guess < target) {
        chat.party("Higher!");
    } else if (guess > target) {
        chat.party("Lower!");
    } else {
        if (timeoutId >= 0) clearTimeout(timeoutId);
        const reward = settings.get("reward");
        economy.add(sender, reward);
        chat.party(`${sender} got it in ${hints} tries! (+${reward} coins)`);
        game.stop();
        return;
    }
    if (timeoutId >= 0) clearTimeout(timeoutId);
    timeoutId = setTimeout(() => {
        chat.party(`Time's up! The number was ${target}.`);
        game.stop();
    }, settings.get("timeout_ms"));
});

game.onStop((reason) => {
    if (timeoutId >= 0) {
        clearTimeout(timeoutId);
        timeoutId = -1;
    }
});

ascii_pictures/module.js — Command module with dynamic commands

Demonstrates: file I/O, JSON parsing, dynamic command registration via command.onCommand, clickgui buttons, refresh pattern.

settings.category("ASCII Pics");
settings.displayName("ASCII Pictures");

settings.toggle({ id: "enabled", default: true });

gui.toggle({ id: "enabled", display: "Enabled" });
gui.button({ id: "open_folder", display: "Open Folder", callback: () => {
    gui.openFolder();
} });
gui.button({ id: "refresh", display: "Refresh", callback: () => {
    refreshPictures();
} });

const pictures = {};

function loadPictures() {
    for (const key of Object.keys(pictures)) {
        delete pictures[key];
    }
    const content = core.readFile("picture-commands.json");
    if (!content) return;
    try {
        const data = JSON.parse(content);
        if (data && data.pictures) {
            for (const p of data.pictures) {
                if (p.name && p.picture) {
                    pictures[p.name] = p.picture;
                }
            }
        }
    } catch (e) {
        console.log("Failed to parse picture-commands.json:", e);
    }
}

function registerPictureCommands() {
    const names = Object.keys(pictures);
    for (const name of names) {
        const lines = pictures[name].split("\n");
        command.onCommand({
            invoker: name,
            callback: (sender, args) => {
                for (const line of lines) {
                    chat.party(line);
                }
            }
        });
    }
}

function unregisterPictureCommands() {
    const names = Object.keys(pictures);
    for (const name of names) {
        command.off(name);
    }
}

function refreshPictures() {
    unregisterPictureCommands();
    loadPictures();
    registerPictureCommands();
    chat.client(`Pictures reloaded (${Object.keys(pictures).length} commands).`);
}

loadPictures();
registerPictureCommands();

command.onCommand({
    invoker: "pictures",
    description: "ASCII picture commands. Loads from picture-commands.json.",
    callback: (sender, args) => {
        const names = Object.keys(pictures);
        if (names.length === 0) {
            chat.party("No pictures loaded. Add them to picture-commands.json and use the GUI to refresh.");
        } else {
            chat.party(`Available: ${names.join(", ")}`);
        }
    }
});

uuid/module.js — HTTP request module

Demonstrates: fetch() polyfill, async/await, dual chat + client command registration.

async function uuidLookup(player) {
    const res = await fetch(`https://api.mojang.com/users/profiles/minecraft/${player}`);
    if (!res.ok) return `Player not found: ${player}`;
    const json = await res.json();
    const raw = json.id;
    return `${json.name}: ${raw.slice(0, 8)}-${raw.slice(8, 12)}-${raw.slice(12, 16)}-${raw.slice(16, 20)}-${raw.slice(20)}`;
}

command.onCommand({
    invoker: "uuid",
    description: "Get a player's UUID.",
    callback: async (sender, args) => {
        chat.party(await uuidLookup(args[0] || sender));
    }
});

command.onCommand({
    invoker: "uuid",
    description: "Get a player's UUID.",
    type: "client",
    args: [{ name: "player", type: "string", optional: true }],
    callback: async (ctx) => {
        chat.client(await uuidLookup(ctx.get("player") || ctx.getSender()));
    }
});

Best Practices

  • Declare metadata first — Call settings.category() and settings.displayName() at the top of module.js, before any other API calls.
  • Split settings from GUI — settings.slider/toggle/text define the data. gui.slider/toggle/text bind a visual widget to that setting by ID. You can have settings without GUI widgets (hidden from user) but not the reverse.
  • Use opts objects for >2 params — gui.button({ id, display, callback }), command.onCommand({ invoker, ... }), settings.slider({ id, default, ... }). No positional args beyond 2.
  • Always clean up timers in game.onStop() — Timers are auto-cleaned on reload, but during normal game flow you should call clearTimeout to prevent stale callbacks.
  • Use chat.onMessage for global hooks, game.onChat for game input — chat.onMessage fires for every message regardless of game state. game.onChat only fires during an active game, and only for party chat.
  • Use const and let over var — GraalJS supports ES2022+.
  • Use console.log for debugging — Native GraalJS global. Supports info, warn, error.
  • Call game.stop() when a game ends — Releases the game slot so other games can start.
  • Settings values are untyped on read — settings.get() returns raw Object. Sliders give Integer, toggles give Boolean, text gives String. There are no separate getBool/getString methods. Returns undefined for non-existent settings.

Edge Cases

  • Game already running: Calling game.start() while a game is active sends "A game is already running!" and is a no-op.
  • Duplicate invoker: Calling command.onCommand() with the same invoker twice in the same module silently overwrites the previous handler.
  • Module evaluation failure: If a module throws during load, it is skipped with chat feedback ("Module 'X' failed: error"). Other modules still load normally.
  • Async callback timing: fetch() resolves on the next client tick after the HTTP response arrives — not immediately. The httpRequestAsync callback follows the same tick-based delivery. Neither blocks the game.
  • Script cleanup: On module reload, all timers, pending HTTP callbacks, command registrations, and chat handlers are automatically cleaned up. Only game.onStop() needs manual attention for game-specific teardown.
