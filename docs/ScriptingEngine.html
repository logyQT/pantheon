Pantheon Scripting Engine

JavaScript-powered modules using Mozilla Rhino

Overview

Pantheon's scripting engine lets you write party games, chat commands, and chat hooks in pure JavaScript. Each module lives in its own folder under config/pantheon/scripts/ and is hot-reloaded on file change.

A module declares what it does by calling lifecycle methods on the pantheon global. The engine reads these declarations after evaluation and automatically wires up commands, game lifecycle hooks, and chat message handlers.

Modules can be toggled on/off via the clickgui. When disabled, their hooks are not called — the script remains loaded but inactive.

Module Structure

Folder layout

Each subfolder under config/pantheon/scripts/ is a module. The name of the folder becomes the module ID.

config/pantheon/scripts/
├── number_guesser/
│   └── module.js              ← entry point (required naming convention)
├── ascii_pictures/
│   ├── module.js
│   └── picture-commands.json  ← module-local asset, read via readFile()
├── wordchain/
│   ├── module.js
│   ├── wordlist.js            ← loaded via require('./wordlist')
│   └── helpers.js
└── lib/
    └── utils.js               ← shared between modules via require('../lib/utils')

Entry point

module.js is evaluated last, after all other .js files in the folder. This means any functions or variables defined in sibling files are available in module.js.

require(path) — explicit imports

Contract: Loads a sibling file and returns its exports object. Path resolves relative to the module folder. Each module has its own require cache — the same file required by different modules gets evaluated separately.
How it works: The engine pre-creates an empty exports object and injects it into the required file's scope. This follows CommonJS conventions but is not Node.js — there is no module or module.exports. Use property mutation (exports.foo = ...) to add values. Do not reassign exports directly (exports = { ... }) — that breaks the return value and your module will receive the original empty object. 
// helpers.js
exports.pickRandom = function(arr) {
  return arr[Math.floor(Math.random() * arr.length)];
};

// module.js
var helpers = require('./helpers');
helpers.pickRandom([1, 2, 3]);

readFile(path) — module-local file access

Contract: Reads a file from within the scripts directory. Paths are relative to the module folder. The path is normalized and checked against the scripts root — any path that escapes config/pantheon/scripts/ is blocked. This means ../lib/utils.js works, but ../../config.json does not. 
// Reads config/pantheon/scripts/ascii_pictures/picture-commands.json
var data = JSON.parse(pantheon.readFile("picture-commands.json"));

// Reads config/pantheon/scripts/lib/utils.js (one level up)
var util = JSON.parse(pantheon.readFile("../lib/utils.js"));

// Blocked: would escape scripts root
pantheon.readFile("../../config.json");  // returns null
Warning: readFile is sandboxed to the scripts directory. It cannot read files outside config/pantheon/scripts/.

Hot reload

The engine watches the scripts directory for file changes. When any .js file in a module folder changes, the entire module is reloaded — old hooks are cleaned up, the module is re-evaluated, and hooks are re-registered. No restart needed.

API Reference

All API methods live under the pantheon global. Each namespace is a public field on the ScriptApi Java object, exposed to JavaScript via Rhino's Context.javaToJS().

Root Methods

pantheon.log(message)

Why: Rhino's sandbox blocks console.log and print (they're removed from the global scope). This is the only way to output debug info to the Java console.
Contract: Prefixes output with [Script:moduleName] for filtering. 
pantheon.log("Debug: " + someValue);

pantheon.getUsername()

Why: Scripts need to know which Minecraft player is running the mod. The username is cached on first call. 
var whoAmI = pantheon.getUsername();

pantheon.getTime()

Why: System.currentTimeMillis() exposed as a convenience method.
Contract: Returns the current system time in milliseconds. Equivalent to Date.now(). Not cached — each call returns a fresh value. 
var startTime = pantheon.getTime();

pantheon.readFile(path)

Why: Modules need persistent config, word lists, or assets. Resolves relative to the module folder. One level of ../ is allowed for shared lib folders.
Contract: Returns null if the file doesn't exist, is unreadable, or if the resolved path escapes the scripts directory. UTF-8 encoding. 
var config = JSON.parse(pantheon.readFile("config.json"));
var shared = pantheon.readFile("../lib/common.json");

Chat all modules

Send messages and receive incoming chat. The sending side uses a queued message system to respect Hypixel's rate limits. The receiving side fires before command routing, so chat hooks see every message.

pantheon.chat.party(message)

pantheon.chat.guild(message)

pantheon.chat.all(message)

Why: Direct message sending bypasses Hypixel's rate limits and gets you muted. These methods queue messages and send them with a configurable cooldown. The queue handles retries on failed delivery.
Contract: Messages 200 or more characters are silently dropped. The queue processes one message at a time with a cooldown (configurable in the "General" settings panel). Messages are prefixed with pc , gc , or ac for Hypixel's channel system. 
pantheon.chat.party("Hello party!");   // Prefixed: "pc Hello party!"
pantheon.chat.guild("Hello guild!");
pantheon.chat.all("Hello world!");

pantheon.chat.command(cmd)

Why: Minecraft commands like /hub need to go through the player's connection, not chat. Also queued for rate limiting.
Contract: No chat prefix is added. The command string is sent via player.connection.sendCommand(). 200 or more characters is silently dropped. 
pantheon.chat.command("/hub");
pantheon.chat.command("msg Notch hello");

pantheon.chat.feedback(message)

Why: Send a message to the local player's chat that only they can see. Unlike party, guild, or all, this is not queued and does not go through the server — it is purely client-side feedback.
Contract: The message is prefixed with [Pantheon] in gold. No rate limits apply. The message is silently dropped if the player is not in-game (e.g., at the title screen). 
pantheon.chat.feedback("Score: 5");
pantheon.chat.feedback("Pictures reloaded (5 commands).");

pantheon.chat.onMessage(callback)

Why: Modules need to react to chat without registering a game or command. This fires for every chat message — party, guild, system, game messages — before any command routing happens.
Contract: The callback receives the raw message text. It fires before FunCommands.processMessage and Meow.handleChat. Multiple onMessage callbacks can be registered from the same module. This hook is not scoped to an active game — it fires regardless. 
pantheon.chat.onMessage(function(rawText) {
  // React to every incoming message
  pantheon.log("Got: " + rawText);
});

pantheon.chat.onMessage(pattern, callback)

Why: Pattern-matching the raw text is the most common use case (e.g., detecting "meow"). This avoids writing the contains() check manually.
Contract: Checks if rawText.toLowerCase() contains pattern.toLowerCase(). Only fires when matched. The callback signature is the same as the raw variant: function(rawText). 
pantheon.chat.onMessage("meow", function(rawText) {
  pantheon.log("Meow detected in: " + rawText);
});

Economy all modules

Server-wide coin economy backed by SQLite. Shared across all modules and persists across restarts.

Why: Games need a reward system. The economy is the only way to give players persistent currency that works across all modules.
Contract: All operations are thread-safe (SQLite). Balances are integers. The take method returns true if successful, false if the player doesn't have enough coins (no negative balances). 
pantheon.economy.add("Notch", 100);
var taken = pantheon.economy.take("Notch", 50);   // false if insufficient funds
var bal = pantheon.economy.balance("Notch");       // 50
var has = pantheon.economy.has("Notch", 30);       // true

Settings & Metadata

Declare configurable values and metadata. Settings appear in the clickgui when you right-click a module. Values are auto-persisted to config/pantheon/config.json.

Why: Scripts need configurable behavior without editing code. The clickgui provides a UI for users to tweak settings at runtime.
Contract: Metadata calls (setCategory, setDisplayName) must happen at the top of module.js. Setting declarations should also be at the top — they're processed during script evaluation. Values are automatically saved to disk when the game exits (ClientLifecycles.CLIENT_STOPPING).

pantheon.settings.setCategory(category)

Defaults to "Scripted Modules" if not called.

pantheon.settings.setCategory("Party Games");

pantheon.settings.setDisplayName(name)

Defaults to the folder name formatted as Title Case if not set.

pantheon.settings.setDisplayName("Number Guesser");

pantheon.settings.addSlider(options)

Only id and display are required. Defaults: min: 0, max: 100, step: 1, default: 0.

pantheon.settings.addSlider({
    id: "reward",
    display: "Reward",
    default: 10,
    min: 1,
    max: 100,
    step: 1
});

pantheon.settings.addToggle(options)

default is false if omitted.

pantheon.settings.addToggle({
    id: "enabled",
    display: "Enabled",
    default: true
});

pantheon.settings.addText(options)

default is "" (empty string) if omitted.

pantheon.settings.addText({
    id: "prefix",
    display: "Prefix",
    default: "!"
});

pantheon.settings.get(id)

pantheon.settings.getBool(id)

pantheon.settings.getString(id)

pantheon.settings.set(id, value)

Why: Settings are typed — get returns int, getBool returns boolean, getString returns string. Using the wrong getter for a setting type returns the default value for that type (0, false, or "").
Contract: get/set operate on the in-memory config cache. Writes are not flushed to disk immediately — they're batched and saved on game exit. If get is called for a setting that doesn't exist, it returns 0. 
var reward = pantheon.settings.get("reward");         // Returns int
var enabled = pantheon.settings.getBool("enabled");    // Returns boolean
var prefix = pantheon.settings.getString("prefix");    // Returns string
pantheon.settings.set("reward", 50);                  // Update at runtime

Dynamic Commands commands

Register additional commands at runtime beyond the module's own pantheon.command.onCommand hook. These are useful for data-driven modules like ASCII Pictures where each picture gets its own !name command.

pantheon.commands.register(name, callback)

Contract: The callback receives (sender, args) where args is a Java String array. The command is registered with a ! prefix. Dynamic commands are automatically cleaned up when the module is reloaded. 
pantheon.commands.register("hello", function(sender, args) {
    pantheon.chat.party("Hello, " + sender + "!");
});

pantheon.commands.unregister(name)

pantheon.commands.unregister("hello");

Clickgui Buttons

Add interactive buttons to the module's clickgui panel.

pantheon.gui.register(id, name, callback)

Why: Some actions (like "Open Folder" or "Refresh") don't belong in a chat command. Buttons in the clickgui are the natural trigger point.
Contract: The id must be unique within the module. The callback takes no arguments. Buttons are registered in ModuleRegistry and rendered by the clickgui. They persist until the module is reloaded or unregister is called. 
pantheon.gui.register("open_folder", "Open Folder", function() {
    pantheon.gui.openFolder();
});
pantheon.gui.register("refresh", "Refresh", function() {
    refreshStuff();
});

pantheon.gui.unregister(id)

pantheon.gui.unregister("open_folder");

pantheon.gui.openFolder()

pantheon.gui.openFolder();

Timers

Schedule delayed callbacks. Fires on the client tick thread.

pantheon.timers.after(delayMs, callback)

pantheon.timers.cancel(timerId)

Why: Games need timeouts (e.g., "answer within 15 seconds"). Rhino doesn't have setTimeout, so this provides the same pattern.
Contract: after takes (ms, callback) — ms first, NOT callback first like setTimeout. The callback takes no arguments. Returns a timer ID (integer) that can be used to cancel. Timers are automatically cleaned up when the module is reloaded or cleanup() is called, but you should still cancel them in onStop to be safe. 
var timerId = pantheon.timers.after(10000, function() {
    pantheon.chat.party("Time's up!");
    pantheon.game.stop();
});

pantheon.timers.cancel(timerId);

Audio all modules

Play sounds from the player's position. Currently supports Minecraft vanilla sounds only — custom file-based sounds are deferred for a future release.

pantheon.audio.playSound(options)

Contract: Plays a Minecraft sound at the player's position. sound is a Minecraft resource location string (e.g., "minecraft:entity.cat.ambient"). volume and pitch are optional, defaulting to 1.0. Silently does nothing if the sound name is invalid or if the player is not in a world. 
pantheon.audio.playSound({ sound: "minecraft:entity.cat.ambient" });
pantheon.audio.playSound({ sound: "minecraft:block.note_block.pling", volume: 0.5, pitch: 1.5 });

Game Lifecycle games

Register lifecycle callbacks for modules that run as a game. Games are stateful — only one game can be active at a time. The engine handles concurrency: if a game is already running, !gamename shows an error instead of starting a new one.

pantheon.game.stop()

Why: Games are stateful — they hold a "game slot" that prevents other games from starting. stop() releases that slot, cleans up timers, and calls onStop.
Contract: No-op if no game is active. Only meaningful inside a game module (one that registered pantheon.game.onStart). Calling from a command does nothing. 
pantheon.game.stop();  // Ends the current game immediately

pantheon.game.onStart(callback)

Contract: Called when the game starts via !modulename. The callback receives the starter's username. The game is marked as "active" before onStart is called, so onTick and onChat will fire immediately.
Auto-command: The engine automatically registers !<folder_name> to start the game. You do not need to call pantheon.command.name() for the game-start command — it exists even if you never set a command name. If you do set pantheon.command.name(), the !<folder_name> game-start command and the !<custom_name> command handler coexist independently. Both onStart and onCommand can be used in the same module.
Why: Without onStart, the module doesn't appear as a playable game in the command system. It's the signal that says "this module is a game." 
pantheon.game.onStart(function(sender) {
    pantheon.chat.party("Game started by " + sender + "!");
});

pantheon.game.onStop(callback)

Contract: Receives a reason string: "MANUAL" (game ended via pantheon.game.stop()), "RELOAD" (module is being hot-reloaded while running), "DISCONNECT" (player left the server), or "DISABLED" (module was toggled off in the clickgui while the game was running). Always clean up timers here — if you don't, they'll fire after the game is over. 
pantheon.game.onStop(function(reason) {
    if (timeoutId >= 0) pantheon.timers.cancel(timeoutId);
});

pantheon.game.onChat(callback)

Contract: Called for each party chat message while the game is active. Receives (sender, message). The message is the text after the : in "Party > PlayerName: message".
Note: This is different from pantheon.chat.onMessage. game.onChat only fires during an active game, and only for party chat messages. chat.onMessage fires for all messages regardless of game state. 
pantheon.game.onChat(function(sender, message) {
    var guess = parseInt(message);
    if (!isNaN(guess)) checkGuess(sender, guess);
});

pantheon.game.onTick(callback)

Contract: Called every client tick while the game is active. A client tick runs roughly 20 times per second. Use this for countdowns, movement checks, etc. 
pantheon.game.onTick(function() {
    // Check elapsed time, update game state, etc.
});

Command Metadata & Lifecycle commands

Register a chat command that users invoke with !name. Unlike dynamic commands (pantheon.commands.register), this is the module's primary command — only one per module.

pantheon.command.name(name)

Contract: Sets the command name. This is what users type after !. If not set, the primary command (onCommand) is not registered. Must be called during script evaluation. 
pantheon.command.name("pictures");

pantheon.command.description(desc)

Contract: Optional. Sets the description shown in the clickgui. If not set, no description is shown. 
pantheon.command.description("ASCII picture commands.");

pantheon.command.onCommand(callback)

Contract: Receives (sender, args) where args is a Java String array. The command is invoked when a user types !commandname arg1 arg2.
Important: You must also call pantheon.command.name() for the command to be registered. If you set onCommand without setting a name, the command is silently skipped.
Why: Having onCommand as a separate lifecycle hook instead of a pantheon.commands.register call makes it clear which command is the module's primary entry point. It also gets cleaned up automatically on reload. 
pantheon.command.onCommand(function(sender, args) {
    if (args.length === 0) {
        pantheon.chat.party("Usage: !hello <name>");
    } else {
        pantheon.chat.party("Hello, " + args[0] + "!");
    }
});

Complete Examples

number_guesser/module.js — Game module

Demonstrates: settings, economy, timers, self-stop, chat input, state machine.

pantheon.settings.setCategory("Party Games");
pantheon.settings.setDisplayName("Number Guesser");

pantheon.settings.addSlider({ id: "reward", display: "Reward", default: 10, min: 1, max: 100, step: 1 });
pantheon.settings.addSlider({ id: "timeout_ms", display: "Timeout (ms)", default: 15000, min: 5000, max: 60000, step: 1000 });
pantheon.settings.addSlider({ id: "max_number", display: "Max Number", default: 20, min: 5, max: 100, step: 1 });

var target = 0;
var hints = 0;
var timeoutId = -1;

pantheon.game.onStart(function(sender) {
    target = Math.floor(Math.random() * pantheon.settings.get("max_number")) + 1;
    hints = 0;
    pantheon.chat.party("I'm thinking of 1-" + pantheon.settings.get("max_number") + ". " + sender + " guesses first.");
    timeoutId = pantheon.timers.after(pantheon.settings.get("timeout_ms"), function() {
        pantheon.chat.party("Time's up! The number was " + target + ".");
        pantheon.game.stop();
    });
});

pantheon.game.onChat(function(sender, message) {
    var guess = parseInt(message);
    if (isNaN(guess)) return;
    hints++;
    if (guess < target) {
        pantheon.chat.party("Higher!");
    } else if (guess > target) {
        pantheon.chat.party("Lower!");
    } else {
        if (timeoutId >= 0) pantheon.timers.cancel(timeoutId);
        var reward = pantheon.settings.get("reward");
        pantheon.economy.add(sender, reward);
        pantheon.chat.party(sender + " got it in " + hints + " tries! (+" + reward + " coins)");
        pantheon.game.stop();
    }
});

pantheon.game.onStop(function(reason) {
    if (timeoutId >= 0) {
        pantheon.timers.cancel(timeoutId);
        timeoutId = -1;
    }
});

ascii_pictures/module.js — Command module

Demonstrates: file I/O, JSON parsing, dynamic command registration, clickgui buttons, refresh pattern.

pantheon.settings.setCategory("ASCII Pics");
pantheon.settings.setDisplayName("ASCII Pictures");
pantheon.settings.addToggle({ id: "enabled", display: "Enabled", default: true });

pantheon.command.name("pictures");
pantheon.command.description("ASCII picture commands. Loads from picture-commands.json.");

pantheon.gui.register("open_folder", "Open Folder", function() {
    pantheon.gui.openFolder();
});
pantheon.gui.register("refresh", "Refresh", function() {
    refreshPictures();
});

var pictures = {};

function loadPictures() {
    pictures = {};
    var content = pantheon.readFile("picture-commands.json");
    if (!content) return;
    try {
        var data = JSON.parse(content);
        if (data && data.pictures) {
            for (var i = 0; i < data.pictures.length; i++) {
                var p = data.pictures[i];
                if (p.name && p.picture) {
                    pictures[p.name] = p.picture;
                }
            }
        }
    } catch (e) {
        pantheon.log("Failed to parse: " + e);
    }
}

function registerPictureCommands() {
    var names = Object.keys(pictures);
    for (var i = 0; i < names.length; i++) {
        var name = names[i];
        var picLines = pictures[name].split("\n");
        (function(lines) {
            pantheon.commands.register(name, function(sender, args) {
                for (var j = 0; j < lines.length; j++) {
                    pantheon.chat.party(lines[j]);
                }
            });
        })(picLines);
    }
}

function unregisterPictureCommands() {
    var names = Object.keys(pictures);
    for (var i = 0; i < names.length; i++) {
        pantheon.commands.unregister(names[i]);
    }
}

function refreshPictures() {
    unregisterPictureCommands();
    loadPictures();
    registerPictureCommands();
    pantheon.chat.party("Pictures reloaded (" + Object.keys(pictures).length + " commands).");
}

loadPictures();
registerPictureCommands();

pantheon.command.onCommand(function(sender, args) {
    if (args.length > 0 && args[0] === "refresh") {
        refreshPictures();
    } else {
        var names = Object.keys(pictures);
        if (names.length === 0) {
            pantheon.chat.party("No pictures loaded.");
        } else {
            pantheon.chat.party("Available: " + names.join(", "));
        }
    }
});

Best Practices

  • Declare metadata first — Call pantheon.settings.setCategory() and pantheon.settings.setDisplayName() at the top of module.js, before any other API calls. These are read by the engine after evaluation.
  • Settings are auto-persisted — Any pantheon.settings.addSlider/addToggle/addText you declare gets automatically saved to config/pantheon/config.json on game exit. If you don't add an "enabled" toggle, one is added for you.
  • Always call pantheon.game.stop() when a game ends — This releases the game slot, cleans up timers, and calls onStop. Without it, the game slot stays occupied and no other game can start.
  • Clean up timers in onStop — Timers are automatically cleaned up on module reload, but during normal game flow you should cancel them in onStop to prevent stale callbacks.
  • Use chat.onMessage for global hooks, game.onChat for game-specific input — chat.onMessage fires for every message regardless of game state. game.onChat only fires during an active game, and only for party chat.
  • Use require() for sharing code — Put shared utilities in a lib/ folder at the scripts root, then use require('../lib/util') from any module.
  • Use require() for splitting large modules — Any .js file in the module folder is evaluated before module.js, but using explicit require() for imports makes dependencies visible.
  • Don't rely on console.log or print — These globals are removed from the sandbox. Use pantheon.log() instead.
  • Settings values are typed — Use get() for integers, getBool() for booleans, getString() for strings. Using the wrong getter returns the type's default (0, false, or "").
  • Hot reload is per-module — Changing any .js file in a module folder reloads the entire module, not just that file. All state is lost on reload.
